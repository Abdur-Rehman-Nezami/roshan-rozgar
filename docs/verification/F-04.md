# F-04 — database implementation checkpoint

The initial SQL migration contains the eighteen tables from BUILD_PLAN.md §6.1, pgvector/pg_trgm/btree_gist extensions, vector/trigram/booking indexes, Haversine function, and `no_double_booking` exclusion constraint for active statuses. Additional checks require bounded, nonempty half-open booking intervals, an expiry on held bookings, and valid monetary ranges. Partial expiry indexes support the eventual sweeper.

`scripts/migrate.mjs` uses the `pg` driver with a single dedicated connection. A session advisory lock serializes deploys. Migration files are versioned and checksummed; changed/missing historical migrations and out-of-order additions are rejected. Each schema change and its ledger insertion share a transaction. The runner never logs connection strings or raw SQL on failure.

`apps/server/src/db/schema.mjs` mirrors the columns, primary/foreign keys, check constraints and indexes as Drizzle definitions. The exclusion constraint and SQL function remain authoritative in the handwritten migration. The mirror is ESM so CLI tooling can load it directly without a TypeScript runtime. **Its Drizzle API compatibility has not been executed**, since Drizzle is unavailable in the package cache. Do not use `drizzle-kit push` to replace or regenerate away the handwritten constraints.
