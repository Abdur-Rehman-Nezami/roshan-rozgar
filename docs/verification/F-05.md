# F-05 — backend foundation checkpoint

Implemented and tested independently of unavailable web/queue dependencies:

- Environment validation requires database/Redis URLs, replacement secrets and HTTPS in production. Error messages expose field names, not submitted values.
- JOSE 6.2.3 signs/verifies HS256 JWT sessions with fixed issuer/audience, expiry and validated subject/role. Cookie helpers set HttpOnly/SameSite/Path and production Secure/host-prefix protections; ambiguous duplicate session cookies fail closed.
- Role guards distinguish unauthenticated and forbidden requests.
- Readiness checks report dependency outages without forwarding driver errors.
- The SQL sweeper expires only pending offers and held bookings based on Postgres time, requiring no Redis. Its scheduler prevents overlapping passes, recovers after errors and waits for a running pass during shutdown.

Nine backend foundation tests pass, bringing the total to 35. Server TypeScript checks pass against the recovered cached packages. The database queries have not been executed against a running database; timer tests verify lifecycle behavior, not SQL race correctness.

## Service/realtime continuation

PG and Redis clients now have connection/command/query time limits and redact errors to fixed event names. `main.ts` uses the real readiness probes and attaches Socket.IO; `jobs.ts` now runs the actual SQL sweeper without creating a Redis connection. The HTTP transport is temporary Node HTTP, pending Fastify installation; it does not satisfy the full F-05 stack gate.

Socket handshakes use signed cookies plus a current DB identity. Thread subscriptions require parameterized DB party membership, search rooms are restricted to customer/city, and user rooms are assigned by the server. Origin checking includes WebSocket upgrades; session expiry disconnects idle sockets. Room operations are serialized and bounded; database/adapter errors return only a generic negative acknowledgement.

PASS: server typecheck; six new security/readiness/socket-policy tests (62 full-suite cases). Socket.IO can be constructed and closed without binding. These checks do not establish live handshake or database correctness. Fastify/helmet/Pino/Redis HTTP rate-limit/static integration, Redis socket adapter, BullMQ, expiry event fan-out and live DB/Redis tests remain open.

References used for the integration: [Socket.IO middleware](https://socket.io/docs/v4/middlewares/), [rooms](https://socket.io/docs/v4/rooms/), [node-postgres pools](https://node-postgres.com/apis/pool). Package APIs were also inspected in the locally recovered pinned sources.
